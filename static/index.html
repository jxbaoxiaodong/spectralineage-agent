Why DataHub?

🔍 Provenance
Every verdict traces back to its exact input spectrum, library version, and rule set. DataHub stores the full lineage graph — not just the result.
🔒 Immutability
SHA-256 checkpoints per stage. If any step is tampered, the audit chain breaks — DataHub records the EXPLICIT_FAIL, not a recalculated verdict.
📊 Governance
Axis Permission Registry: KG and RAG axes are forbidden from writing resolved_level or direction_label. Only the LLM axis, after Evidence Gate, can conclude.
🔁 Reproducibility
Any prior verdict can be replayed from DataHub: same spectrum URN, same pipeline version, same rule set version → deterministic output.

DataHub Integration Points Used

✅ DataHub Python SDK — DatahubRestEmitter + MetadataChangeProposalWrapper
✅ DatasetProperties — spectrum metadata + verdict metadata as custom properties
✅ UpstreamLineage — spectrum → verdict edge with TRANSFORMED type
✅ DataFlow + DataJob — pipeline and Evidence Gate step as first-class entities
✅ DataJobInputOutput — explicit I/O binding of the job to datasets
✅ Status — entities marked active (not removed)
✅ REST API — lineage queries via /openapi/v3/relationships
